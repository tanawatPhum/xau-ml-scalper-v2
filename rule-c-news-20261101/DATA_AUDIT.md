# FOMC timestamp audit — 1 November 2026

The provided files support a small diagnostic using eight regular 2016 FOMC statements. They do not support a well-powered 2010–2016 news test, comprehensive news/no-news classification, or proof of actual dissemination latency. No price data were used in this audit.

The two source CSVs contain `date,time_et,title,url`; their 2010–2019 slices are identical:82 rows,80 regular meeting policy statements, one2010-05-09 liquidity-swap conference-call statement, and one2019-10-11 implementation notation-vote statement. There are no duplicate dates or URLs. The full source-file counts109/110 include permitted announcement metadata beyond2019; all output manifest rows are restricted to2010–2019. Source paths and SHA-256 hashes are in INPUTS.json. No original files were modified.

Every one of the34 explicit CSV times was independently checked against a date-specific Federal Reserve HTML header. All matched HH:MM and EST/EDT, and the zone abbreviation matched America/New_York's date-specific DST offset. Winter14:00EST converts to19:00UTC; summer14:00EDT converts to18:00UTC. In particular2016-11-02 remains EDT. Eight design-page last-update dates match their event date. No observed intraday correction/version history or actual wire-delivery latency is available; same-date last update is not proof of no correction.

Example primary sources: [2016-01-27](https://www.federalreserve.gov/newsevents/pressreleases/monetary20160127a.htm), [2016-03-16](https://www.federalreserve.gov/newsevents/pressreleases/monetary20160316a.htm), [2016-11-02](https://www.federalreserve.gov/newsevents/pressreleases/monetary20161102a.htm), [2016-12-14](https://www.federalreserve.gov/newsevents/pressreleases/monetary20161214a.htm). Each full event URL is retained in the manifest alongside its evidence-file hash. source_evidence files contain web-tool extraction responses, not byte-identical downloaded HTML; their hashes verify the saved extraction artifact, not the original HTTP bytes. The original local annual archive pages have separate byte hashes. Direct shell HTTP fetching failed DNS resolution; the primary web tool supplied the verification.

All48 regular statements from2010–2015 lack a release minute in both local CSVs. Bounded live checks covered one date in each of those six years: [2010-01-27](https://www.federalreserve.gov/newsevents/pressreleases/monetary20100127a.htm), [2011-04-27](https://www.federalreserve.gov/newsevents/pressreleases/monetary20110427a.htm), [2012-04-25](https://www.federalreserve.gov/newsevents/pressreleases/monetary20120425a.htm), [2013-03-20](https://www.federalreserve.gov/newsevents/pressreleases/monetary20130320a.htm), [2014-03-19](https://www.federalreserve.gov/newsevents/pressreleases/monetary20140319a.htm), [2015-06-17](https://www.federalreserve.gov/newsevents/pressreleases/monetary20150617a.htm). All six say only immediate release, with no statement PDF exposed in the returned page links. The2010 archive links statement HTML and other materials but does not itself supply a statement release minute. This bounded check does not claim no recoverable original PDF/archive exists anywhere; no guessed PDF URL or default clock time was substituted.42 of48 missing-time rows were not independently re-fetched and remain explicitly unverified at page level.

The source downloader extracts `monetary...a.htm` links from annual FOMC archives and then filters titles containing statement. It therefore covers a narrow statement subset rather than all monetary announcements, minutes, press conferences, speeches, macro releases, or unscheduled news. Its date-keyed dictionary can silently collapse same-date links, and its `a.htm` restriction excludes other letter-suffixed companion releases. The repair script only reparses missing header times, but neither source script stores individual statement HTML, publication timestamps, raw header timezone, or revision provenance in the CSV. The expected SOURCES.json was absent at audit start. Neither source script was rerun. No macro values, surprise estimates, GVZ prices, US500 prices or2020+ quote files were read.

The [2010-05-09 statement](https://www.federalreserve.gov/newsevents/pressreleases/monetary20100509a.htm) concerns swap facilities and its page last update isMay10. The [2019-10-11 statement](https://www.federalreserve.gov/newsevents/pressreleases/monetary20191011a.htm) describes an implementation notation vote and has anOctober15 update. Both have verified declared clocks but are outside the fixed regular policy-decision universe. Annual archive headings classify regular meetings versus a conference call/notation vote; there is no saved pre-event calendar snapshot proving when the schedule itself was publicly known. The diagnostic uses the statement's declared release header, not calendar expectations alone.

`declared_release_at_utc` contains only explicit official minute evidence. `actual_available_at_utc` stays blank for every row. Published 'For release at' instructions are a stronger basis than a customary clock but do not establish actual historical feed latency. The limited diagnostic accepts that declared-time proxy and labels it. Unknown dates/times remain unknown-news; no quiet/no-news control is constructed. The frozen universe cannot be expanded after inspecting diagnostic returns.

For a future portable import, supply at least event_id, event_type, regular/scheduled/unscheduled classification, event_date, scheduled_at_utc, declared_release_at_utc, actual_available_at_utc, timestamp_basis, precision, source_timezone, source_url, fetched_at_utc, raw_source_sha256, revision_id, supersedes_event_id, and coverage_scope. Preserve unknown timestamps as null. Require offset-aware UTC conversion verified against date-specific timezone, a date-specific evidence excerpt for each included minute, unique event/revision keys, no silent same-date deduplication, and no inferred availability from price jumps. Separate original/correction releases and avoid using revised numerical data as contemporaneous surprises. Test date/URL agreement, timezone/DST, duplicates, missing minute rejection, event time no later than signal knowledge, and explicit coverage bounds. Actual observed dissemination data would strengthen the current proxy.
